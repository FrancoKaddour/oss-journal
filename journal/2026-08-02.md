# 2026-08-02 — Three verified fixes in one day (Storybook + TanStack Router ×2)

Biggest single-day output of the mission so far: three draft PRs, each root-caused to exact files/lines and verified against a real reproduction before publishing.

## [storybook#35706](https://github.com/storybookjs/storybook/pull/35706) — TanStack Start + Cloudflare (closes #35704, filed hours earlier)

`@storybook/tanstack-react` + `@cloudflare/vite-plugin` crashed Storybook at startup: the Cloudflare plugin boots workerd inside Storybook's dev server and evaluates `virtual:cloudflare/worker-entry` there; Storybook's module interception resolves that entry to its TanStack Start mock, which imports `storybook/test` — rewritten by the Vite builder to a global that only exists in the browser preview. `ReferenceError` inside workerd.

Fix: drop the Cloudflare plugin from the Vite config Storybook inherits (it's never needed — every Start server module is mocked), following the same pattern used for the TanStack Start plugins themselves. Extracted the plugin predicates into a unit-tested module. Verified against the reporter's repro on Windows: baseline fails with the exact stack from the issue; with the fix, Storybook starts and builds the preview in ~5s.

## [router#7937](https://github.com/TanStack/router/pull/7937) — Module Federation regression (closes #7921)

Bisected a `1.168.16 → 1.168.17` regression to the single router-plugin commit in that bump: the injected Vite HMR preamble started *eagerly* patching whatever route `window.__TSR_ROUTER__` holds under the same route id — on first import, not just on hot re-evaluation. With two routers in one window (module federation host/remote), ids like `__root__` collide, the global is last-created-wins, and the remote's modules graft the host's components into their own route tree → "Invalid hook call" across two React copies.

Fix: `hot.data` persists across re-evaluations but starts empty on first import — exactly the missing discriminator. Gated the eager patch behind a persisted flag; the original aliased-HMR fix keeps working. 749/749 tests green, snapshots regenerated (the diff is precisely the three gate lines).

## [router#7938](https://github.com/TanStack/router/pull/7938) — 76 MB leaked into the RSC bundle (closes #7934, filed the same day)

The RSC helpers imported `getRequest` from the `start-server-core` root barrel; the barrel re-exports `createStartHandler`, whose dynamic `#tanstack-router-entry` import survives into the RSC build and drags the *unpruned* route tree — every server route and its heavy imports — into a duplicate chunk. Two-line fix: import from the self-contained `/request-response` subpath instead.

Verified against the reporter's repro: baseline emits a 76 MB `router-*.js` chunk (153 MB dist); with the change, the chunk is gone and dist drops to 78 MB.

# 2026-07-30 — First code PR to the Ark/Zag ecosystem

## Zag #3231 → PR #3233 (marquee speed viewport-independent)

Scouted fresh Monday candidates across 5 repos; timeline check killed 6/7 (foco repos move fast), leaving Zag #3231 — a rare *bounded* bug in a well-maintained repo.

Root-caused and verified empirically: the marquee derives `--marquee-duration` from `rootSize`, but each content element translates by `100%` of its own size (`translateX(100%)` in the keyframes), so the real animation distance is always `contentSize`. When content is smaller than the viewport, the configured `speed` scales by `contentSize/rootSize` — the reporter's 1000px/100px/speed-100 case ran at 10px/s instead of 100.

Fix: `contentSize / speed` for the non-autoFill branch. Moved `calculateDuration` to `marquee.utils.ts` (following Zag's utils-test convention) and added `tests/marquee.utils.test.ts` — 4 cases incl. the regression and a `contentSize/duration === speed` invariant. Red-green verified (3 bug tests fail against the old rootSize logic), typecheck + eslint clean, changeset added. [PR #3233](https://github.com/chakra-ui/zag/pull/3233).

First code contribution to Ark UI / Zag.js — the growth-stage bet, now with a real PR (analysis debut was #3203).
